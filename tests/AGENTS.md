# Tests

- Keep test files flat at `tests/<name>.test.ts` (`npm test` globs `tests/*.test.ts` with a 120s per-test timeout; nested subdirectories never run). Use `node:test` and `node:assert/strict`, importing source by `.js` path (`../src/server/workers.js`, resolved by `tsx`).
- `npm run test:coverage` enforces the line and function floors in `package.json` across `src/` and `bin/` (`tests/**` excluded). Add tests when changes drop either floor; lower a floor only to the actual suite coverage when removing covered code, in the same change.
- When pairing a fake clock with real async work (file I/O, stubbed commands or fetches), await work completion before advancing the clock or asserting rather than sleeping for fixed real time (follow the rig in `tests/subscriptions-state.test.ts`). Stress-test with random delays across parallel runs before shipping.
- Put temp fixtures under `os.tmpdir()` cleaned up in `t.after`, stub external CLIs (`git`, `gh`, providers), and stay off the network and this checkout's `.factory-flow/`. Derive every stubbed API body or CLI output from a real capture on the owner's account (trimmed, secrets replaced); user-visible changes still follow "Testing the running office" in the root [AGENTS.md](../AGENTS.md).
- A test file that asserts on git's view of a folder or on the `GIT_CEILING_DIRECTORIES` the office hands to its children starts with `import './hermetic-git.js';`, so git variables inherited from the process running the suite (a Mission Control session's ceiling, a git hook's `GIT_DIR`) can't change the result. Import it per file: a relative `--import` in the npm scripts is inherited by the PTY host and every other spawned Node child, which can't resolve it from their own working folders.
